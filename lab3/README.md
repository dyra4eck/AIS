* **predict** — предсказание «переход не выполняется» с аннулированием команд

* **stall** — приостановка выборки до вычисления условия перехода (для сравнения).

## 2. Математические модели процессорного ядра

### Модель 1. Время выполнения одной команды

Определим для команды k (в порядке выполнения программы):

* **F_k** — такт выборки (ступень IF);
* **C_k** — такт записи результата (ступень WB);
* **L_k = C_k − F_k + 1** — латентность, от выборки до записи результата;
* **S_k** — такт, в котором команду можно было бы выбрать при отсутствии конфликтов:
  в той же группе, что и предыдущая команда (S_k = F_{k−1}), если k следует в памяти
  сразу за k−1 и k−1 стоит не в последнем конвейере; иначе в следующем такте
  (S_k = F_{k−1} + 1);
* **W_k = F_k − S_k** — задержка выборки из-за конфликта по управлению;
* **T_k = L_k + W_k** — время выполнения команды с учётом конфликта.

**Латентность.** В ядре нет приостановок внутри конвейера: конфликты по данным
исключены условием задания, а конфликт по управлению влияет только на выборку.
Каждая команда проходит 4 ступени по одному такту:

    L_k = S = 4   для команд всех типов.

**Задержка выборки.** Рекуррентная модель выборки: команда k попадает в группу
команды k−1 (g_k = 1), если pc_k = pc_{k−1} + 1, slot_{k−1} < P − 1 и:

* predict: k−1 — не выполненный переход;
* stall: k−1 — не переход (группа обрывается после любого JL).

Тогда

    F_k = F_{k−1},                        если g_k = 1
    F_k = F_{k−1} + 1 + D · b_{k−1},      иначе,

где b_{k−1} = 1, если k−1 — выполненный JL (predict) или любой JL (stall).
Номер конвейера slot_k = slot_{k−1} + 1 при g_k = 1, иначе 0. C_k = F_k + S − 1.

Отсюда возможные значения задержки W:

| Ситуация | predict | stall |
|---|:---:|:---:|
| перед командой нет перехода | 0 | 0 |
| команда — адрес выполненного перехода | D = 2 | D = 2 |
| команда следует за невыполненным JL из последнего конвейера группы | 0 | D = 2 |
| команда следует за невыполненным JL из конвейера 0 или 1 (без конфликта попала бы в ту же группу) | 0 | D + 1 = 3 |

### Модель 2. Время выполнения последовательности команд

Время участка программы — от выборки его первой команды до записи результата последней:
T = C_end − F_start + 1. Из модели 1 следуют формулы в замкнутом виде.

1. **N команд без переходов** (участок начинается с начала группы):

       T(N) = ⌈N / P⌉ + S − 1

2. **N невыполняемых переходов подряд:**
   predict — как (1); stall — каждый JL образует свою группу и занимает D + 1 такт:

       T_stall(N) = (D + 1)(N − 1) + S = 3N + 1

3. **Цепочка из B блоков (одна группа), каждый заканчивается выполняемым переходом на
   следующий блок** (обе стратегии): T = (D + 1)(B − 1) + S (последний блок — только JL
   в конвейере 0).

4. **B блоков по k команд (k кратно P), в конце блока JL, выполняется n_t переходов
   (не считая последнего блока):**

       predict:  T = B·k/P + D·n_t + S − 1
       stall:    T = B·k/P + D·(B − 1) + S − 1

### Модель 3. Производительность и пропускная способность

Производительность — IPC = N / T (команд за такт), обратная величина — CPI.
Пропускная способность — предел IPC при N → ∞ (установившийся режим).

При доле переходов b среди команд и вероятности выполнения перехода p (переходы в
последнем конвейере группы) из модели 2:

    CPI_predict = 1/P + D·b·p
    CPI_stall   = 1/P + D·b

Выигрыш предсказания: CPI_stall / CPI_predict = (1/P + D·b) / (1/P + D·b·p);
при p = 1 алгоритмы равноценны.

## 4. Алгоритмы тестов

Все тесты сгенерированы [`tools/gen_tests.py`](tools/gen_tests.py) и соблюдают условие
отсутствия конфликтов по данным: регистр, записанный в группе g, читается не раньше
группы g + 2 (регистры чередуются по группам). Это контролирует монитор из ЛР2.
Кроме того, итоговые память и регистры в каждом прогоне сверяются с эталонной моделью.

### Тесты минимального времени (конфликтов нет)

* **`min_all`** — пять участков по 30 однотипных команд: ADD, SUB, LOAD, STORE, NOP
  (по 3 в группе, наборы регистров-приёмников чередуются по группам). Переходов нет,
  поэтому все команды должны выполняться за T_min = 4, а каждый участок —
  за ⌈N/P⌉ + S − 1 тактов.
* **`min_jl`** — 30 невыполняемых JL подряд (флаги заранее установлены в «не <»).
  Для predict это случай без конфликта; для stall — наихудший поток переходов
  (каждый JL приостанавливает выборку).

### Тесты максимального времени (конфликты с наибольшими задержками)

* **`max_taken`** — цепочка из 24 блоков по одной группе. Каждый блок стоит по адресу
  выполняемого перехода из предыдущего блока, первая команда блока — команда
  исследуемого типа (ADD, SUB, LOAD, STORE, NOP, JL по очереди, по 4 раза). Флаги всё
  время дают «<» (ADD и SUB подобраны так, что результат остаётся отрицательным).
  Каждая команда по адресу перехода должна иметь W = D, T = 6 в обоих режимах.
  Блоки с JL в конвейере 0 дают и максимальное число аннулированных команд (8).
* **`max_seq`** — 24 пары «JL (не выполняется), X», X — команда исследуемого типа.
  Для stall каждая X следует за JL из конвейера 0 или 1 и должна иметь
  W = D + 1, T = 7. Для predict тот же тест выполняется без потерь (T = 4).

### Синтетические программы

* **`bench_k{3,6,12}_p{0,50,100}`** — 72 команды: блоки по k команд (k − 2 команды
  ADD, команда установки флагов, JL в последнем конвейере группы). Переход всегда
  направлен на следующий блок, поэтому путь выполнения один и тот же, а выполняется ли
  переход — задаётся флагами (p = 0 — никогда, 50 — через блок, 100 — всегда).
  Позволяют оценить производительность в зависимости от доли переходов b = 1/k и
  вероятности перехода p.

Измеряемые участки отмечаются в исходном тексте директивами `.region имя` /
`.endregion` (ассемблер ЛР2 записывает их в файл `ИМЯ.regions`).

## 5. Механизмы измерения времени в тестовом окружении

Реализованы в [`tb/tb_perf.vhd`](tb/tb_perf.vhd).

**Метка такта выборки.** В записи конвейерных регистров добавлено поле `tf`. При
выборке в него заносится номер текущего такта (счётчик тактов ядра), далее метка
передаётся вместе с командой по ступеням OF → EX → WB. Команды на ступени WB вместе
с метками выдаются на порт `dbg_retire`.

**Регистрация команд.** На каждом спаде синхросигнала окружение просматривает слоты
0, 1, 2 порта `dbg_retire`, т.е. завершающиеся команды в программном порядке. Для каждой
команды:

1. F = tf, C = номер текущего такта, L = C − F + 1;
2. S = F предыдущей команды, если текущая следует за ней в памяти, а предыдущая была
   не в конвейере 2; иначе S = F предыдущей + 1;
3. W = F − S, T = L + W;
4. строка журнала `results/ИМЯ.РЕЖИМ.instr.csv`: номер, такт WB, конвейер, адрес, тип,
   F, L, W, T;
5. накопление по типу команды: количество, минимум и максимум L, W, T, сумма T (среднее).

**Измерение участков.** Из файла `ИМЯ.regions` читаются адреса первой и последней
команды каждого участка. При завершении команды с адресом начала участка (первый
раз) запоминаются F_start и порядковый номер команды; при каждом завершении команды
с адресом конца — C_end и номер. В конце: T = C_end − F_start + 1, N — число команд,
завершённых за это время, IPC = N/T, CPI = T/N.

**Итог** выводится на экран и в `results/ИМЯ.РЕЖИМ.perf.txt`, например:

```
=== max_seq [stall]  cycles=92  retired=61  squashed=0  taken=0  stall=57
type    count  L min  L max  W min  W max  T min  T max  T avg
NOP        12      4      4      0      3      4      7   5.00
LOAD        5      4      4      0      3      4      7   6.40
STORE       4      4      4      3      3      7      7   7.00
ADD         7      4      4      0      3      4      7   5.71
SUB         4      4      4      3      3      7      7   7.00
JL         28      4      4      0      3      4      7   4.75
region pairs                    T=85 N=48 IPC=0.56 CPI=1.77
```

(Минимальные значения в тестах максимального времени дают команды начальной
установки констант, стоящие до первого перехода.)

Расхождение не превышает 0.042 = (S − 1)/N: модель 3 описывает установившийся режим и
не учитывает заполнение конвейера (3 такта на участок); с ростом N оно стремится к нулю.
Точная модель 2 учитывает заполнение и совпадает с измерениями.

Модели 1 и 2 совпали с моделированием точно, потому что ядро детерминировано:
конвейер без приостановок внутри, конфликты по данным исключены, а поведение при
конфликте по управлению (потеря D тактов, обрыв группы) полностью описано моделью.
Модель написана независимо от RTL (на Python, по описанию алгоритма), поэтому
совпадение подтверждает и модель, и корректность реализации алгоритма в RTL.

## 8. Выводы

1. Латентность любой команды — 4 такта (по числу ступеней): внутри конвейера
   приостановок нет. Конфликт по управлению проявляется как задержка выборки
   последующих команд, одинаковая для команд всех типов.
2. Минимальное время выполнения команды любого типа — 4 такта, максимальное —
   6 тактов при предсказании (команда по адресу выполненного перехода) и 7 тактов при
   приостановке выборки (команда, которая без конфликта попала бы в одну группу с
   предшествующим JL). Теоретические оценки подтверждены моделированием.
3. Пиковая пропускная способность — 3 команды за такт для всех типов команд, кроме
   переходов: невыполняемые JL при предсказании — 3 за такт, при приостановке —
   1/3 за такт; выполняемые JL — 1/3 за такт при обоих алгоритмах. Поток из
   30 однотипных команд выполняется за 13 тактов (IPC 2.31, ⌈N/3⌉ + 3).
4. Производительность определяется долей переходов b и вероятностью перехода p:
   CPI ≈ 1/3 + 2·b·p при предсказании и 1/3 + 2·b при приостановке. Предсказание
   никогда не проигрывает и выигрывает до 2.7 раза (b = 1/3, p = 0); при p = 1 алгоритмы
   равноценны, но предсказание выполняет лишнюю работу (до 8 аннулированных команд
   на переход).
5. Аналитическая модель (рекуррентная и формулы в замкнутом виде) точно совпала с
   моделированием для всех 26 прогонов и всех 2 282 выполненных команд; асимптотическая
   модель CPI отличается от измерений на участках из 72 команд не более чем на
   (S − 1)/N ≈ 0.04 из-за заполнения конвейера.
